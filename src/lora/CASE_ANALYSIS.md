# MATH LoRA典型案例初步分析

来源：全754验证的before与validation_400，以及正在运行的32题token诊断。前者是step400，后者比较step800；不得混称同一checkpoint。原数据ID含train字样，但这些ID属于冻结的validation划分。

## 非截断退化

两次均未截断、基线正确而step400错误的题共110道。这是单次采样的观察，不证明每题变化的唯一原因。

1. algebra/train/376：a@b=3a−3b，求3@5。基线3(3)−3(5)=−6；LoRA写成(3−5)(0)=0。错误发生在代入规则，不是回答长度。
2. prealgebra/train/389：(4+8)^2+(4^2+8^2)。基线144+80=224；LoRA列出12^2+4^2+8^2，却给208。展开正确、数值汇总错误，且已正常闭合answer。
3. prealgebra/train/396：sqrt(2^2*3^4)。基线sqrt(324)=18；LoRA得到2^(2/2)*3^(4/2)，却给6。指数化简后的计算错误，并非缺少token预算。

## 新token诊断的早期例子

intermediate_algebra/train/1115：七次单位根的幂次和。baseline开头正确讨论指数模7，随后在omega^20处生成binary:E unluckyhos ConfigureARC等无关文本；1024与2048均截断、评分均0。此例更符合生成偏离任务导致耗尽预算，不是连贯推导仅差最后几步。它发生在零adapter基线，不能归因于此次LoRA；但还不能区分原GRPO权重、采样或推理实现的贡献。

32题诊断尚未完整结束，不能据早期案例估算总体token收益。代码保存同一2048轨迹的1024前缀用于配对比较。

## 后续方向

先汇总token诊断的截断→正确收益和原本正确→错误数量。若多数延长只是重复或无关文本，不优先提高所有评估预算。需要在隔离验证中比较GRPO与较早DPO/SFT基座生成稳定性，不能基于测试集选基座。学习率/alpha/rank/层范围均缺少单变量对照；后14/7层尚未运行，无法判断某层是根因。当前已暂停正式训练和队列，保留原断点。
