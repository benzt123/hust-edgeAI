## 完整测试结果

同一GSM8K官方test的1319道题、相同prompt/生成参数/评分器gsm8k_numeric_v1。

| 指标 | Base | 最佳SFT（第2000步） |
| --- | ---: | ---: |
| 答案正确率 | 2.20%（29/1319） | 66.57%（878/1319） |
| 严格格式通过率 | 25.78% | 99.92% |
| 答案解析率 | 5.76% | 99.77% |
| 答案正确且格式正确 | 1.36% | 66.57% |
| 生成截断率 | 3.41% | 0.08% |
| 标准解答条件下平均loss | 0.8251 | 0.4496 |

准确率提升64.37个百分点，但不能全解释成数学推理能力提升：Base绝大多数回答未被保守评分器解析，SFT同时学会了指定的输出格式。这是当前协议的端到端表现，不是该模型的通用能力或官方基准成绩。解析失败按错计，格式率和解析率的规则不同，因此两者不必一致。

## 如何理解训练轮数

第1轮末（841步）验证loss为0.3533、固定50题正确率40%；第2轮末（1682步）loss为0.3681、正确率70%；第3轮末（2523步）loss为0.4494、正确率64%。验证正确率最高在2000步，为76%，按预先规定的规则选为best_model。

验证loss是给定标准答案前文时，模型对后续标准token的预测误差；生成准确率衡量模型独立生成的最终答案是否正确，因此两者不保证同步变化。后期loss上升、最后模型生成正确率回落，有过拟合迹象，但50题每错一题就变化2个百分点，也存在较大的采样波动。不能单凭这一条曲线断言已确定最佳训练轮数。

## 下一轮调整建议（尚未执行）

1. 先人工抽查Base解析失败样本和SFT错误样本，区分格式问题、提取漏判和真正的数学错误。若改评分器，应两边统一重评，保留本版结果；不要仅为提高测试分数修改规则。
2. 增大固定验证生成样本数，例如200题，减少仅50题选模型的波动；后续选择参数继续使用验证集，不使用已看过的test结果调参。
3. 以2轮作为下一次对照候选；也可单独测试更低峰值学习率，例如5e-6。每次只改一个因素，不能从本次实验保证这些设置一定更好。
4. 保留micro-batch=4、有效batch=8的已验证执行方式。短测速率从1.09降至0.60秒/更新；验证和18.5GB断点写入仍是明显开销。
